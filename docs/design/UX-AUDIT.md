# UX 审计：dsh-task-gantt（v0.2.38，480px 侧边栏面板）

> 结论全部可回溯到源码 `文件:行号`（仓库相对路径）。对比度数值由主题 token 实测值计算（`tests/fixtures/theme-token-values.json`、宿主主题包提取值，见 `docs/THEME-FACTS.md`），WCAG 判据：正文 4.5:1、图形/大字 3:1、点击目标 24×24（WCAG 2.2 AA）。
> 现状结构、文案与交互全量清单见 `docs/design/AS-IS-INVENTORY.md`（下称「清单」）。**红线**（用户已明确要求、改版不可推翻的设计）见清单 §5，本文只在不触碰红线的范围内给改法。

## 0. 结论摘要

| 维度 | 结论 |
|---|---|
| 可用性硬伤 | 6 条 P0：**首屏空白（加载/错误态不可达）**、工具栏在设计宽度就溢出且无可见滚动条、任务条点击区=绘制宽度（可细到 1px）、等待条亮色皮肤不可见、两个详情面板可同时挤掉图区、全图数据文本 11px + 3.71:1 |
| 层级与噪声 | 9 条 P1：方向编码退化、状态字形无图例、图例一栏三用、列头语义错位、冻结态无区分、浮窗不可交互、"仅 title"信息不可达、时段锚点只修了一半、原始 id 泄漏 |

## 1. P0 — 可用性 / 可读性硬伤

### P0-01 加载态与错误态**永不可达**：首屏是空白面板，失败后也没有重试入口

- **证据**：`BoardView.tsx:332-335` 里 `shownData = data === null ? null : filter(...)`；紧接着 `BoardView.tsx:499-501` `if (shownData === null) return null`（早于 `503-520` 的 loading/error 分支）。二者等价于「`data === null` → 渲染 null」，`503-520` 整段是死代码。
- **用户感知**：首次打开或接口失败时面板一个字都没有，用户会判断"插件坏了/没装"；唯一的重试是工具栏最右侧 `⟳`（`BoardView.tsx:591-593`），而它在同一行的溢出区里可能根本不在视口内（见 P0-02）。轮询失败也是同样结果：`error` 有值但首屏仍空白。
- **改法**：把 `499-501` 改成 `if (data === null) return <CenterState .../>`（保留 `503-520` 的语义）。中心态建议：容器 `min-height: 240px`、标题 14px/500 primary、正文 12px/18 secondary、可选主按钮 28px 高（`padding 0 12px`, `radius 6`）；加载态用 3 行骨架条（宽 60%/45%/30%，高 8px，`bg-layer-3`，`radius 4`）替代纯文字；错误态必须同时给出 `error.code`（`api.ts` 的 envelope 已带）与「重试」。

### P0-02 工具栏在 480px 设计宽度下横向溢出，而滚动条被主动隐藏

- **证据**：`.dtg-bar` `overflow-x:auto; scrollbar-width:none`（`styles.ts:48-50`）；所有直接子元素 `flex:0 0 auto`（`styles.ts:79`），chip 与按钮都 `white-space:nowrap`（`styles.ts:66,93`）→ **没有任何一项可收缩**。8 个控件（`BoardView.tsx:531-593`）的内联宽度估算合计 ≈ 490px（11px CJK≈11px/字、拉丁≈6px/字，已计 padding/border 与 7×4px gap，估算误差 ±10%）；冻结态把「现在」chip 换成 `MM-DD HH:mm:ss → 结束 …`（`BoardView.tsx:537-540`）再 +200px。
- **用户感知**：右端的「任务数」「刷新」被推出面板；因为滚动条不可见，用户不知道这一行还能横滚。截图（v0.2.11，尚无「筛选」按钮）里内容右缘已贴到面板边缘，当前版本又多一个 ~85px 按钮 —— 必溢出。
- **改法**：单行预算 ≤ 448px（480 − 2×16）。具体：来源 chip 收敛为 24×24 图标 + tooltip（省 ~78px）；「跟随时间线」改 24×24 图标按钮（省 ~47px）；「筛选 teammate」改 24×24 漏斗图标 + 右上 12px 徽标显示已隐藏数（省 ~50px）；刷新 ⋯ 收纳进右侧 overflow 菜单（省 ~23px）；`时间段` 的 label 去掉，只留 select（省 ~36px）。保留：现在/冻结 chip（宽度上限 112px，超出省略 + 全量 tooltip）。或改为**两行**：第一行状态（来源+现在/时段+任务数），第二行视图（时段+跟随+筛选）。

### P0-03 任务条的点击目标 = 它被绘制的宽度（可以只有 1px），且没有外扩热区

- **证据**：任务条 `width = max(1, duration/msPerPx)`（`timeline-layout.ts:312-330,2383`）；非历史任务是 9px 固定标记（`timeline-layout.ts:341,2390-2391`）；`.dtg-task` 没有热区伪元素（`styles.ts:317-338`），而同一张图上的消息标记专门做了 `::before` 外扩 5px（`styles.ts:893-904`）。
- **用户感知**：25ms/px 这类粗粒度下，5 秒任务就是一条 1px 竖线，鼠标几乎点不中；「点开详情」这个核心操作在图上变成碰运气。键盘可达但没人会用 Tab 遍历几十个任务。
- **改法**：给 `.dtg-task` 加透明热区 `::before { position:absolute; inset:-8px -6px; }`（绝对定位热区不参与布局，条长不变，符合红线 R3/R5）；同时把 `aria` 之外的命中最小宽度做到 20px：热区 `min-width:20px` 用 `left:-6px; right:-6px` 撑开；`data-task-anchor='live'` 的 9px 标记同样外扩到 20×20。z-index 让相邻热区按"后绘制优先"或加 1px 间隙避免误点（相邻条可优先选更近的中心）。

### P0-04 等待条在亮色皮肤下几乎不可见（叠加后 1.68:1，`unknown` 仅 1.40:1）

- **证据**：`.dtg-wait` = `label-tertiary` + `opacity:.45`（`styles.ts:671-677`），`unknown` 再降到 `.3`（`styles.ts:717`），`timeout` `.6`（`styles.ts:716`）；亮色 skin 的 `label-tertiary=#81858c` 叠加在 `#fff` 上 → `#c6c8cb` ≈ **1.68:1**，0.3 时 ≈ **1.40:1**，均低于 3:1 图形下限。暗色 skin 分别 ≈2.61:1 / 1.88:1，同样不及格。而它承载的信息（agent 在等谁、等满还是被叫醒）只能从这层纹理读出。
- **用户感知**：「等满超时，没人来」这条最有价值的信息在亮色皮肤上等于没画；用户会以为那些时间片是空闲或未采集。
- **改法**：去掉整体透明度，改用**形状编码**：条体填 `label-secondary`（亮 5.80:1 / 暗 10.42:1）但只画 2px 高的上下边 + 内部 1px 斜纹（保持现有 mask 思路）；或条体保留 3px 高的不透明带 + `opacity:1`；四种结果继续用右端 cap 形状区分（现有语义不变，红线 R10 只要求"重合在 span"）。`unknown` 不要降到 0.3，改用"点线边框"表达不确定。

### P0-05 任务详情与消息详情可同时打开，`45% + 60%` 把图区挤到 0 高

- **证据**：两个面板是并列兄弟节点（`BoardView.tsx:635-653`），注释明确"两者可同时开"（`BoardView.tsx:293-298`）；`.dtg-details` `flex:0 0 auto; max-height:45%`（`styles.ts:1139-1146`），`.dtg-message-details` `max-height:60%`（`styles.ts:778`）；图区 `.dtg-body` 是 `flex:1 1 auto; min-height:0`（`styles.ts:103-109,258`）→ 两块详情内容都足够长时合计可达 105%，图区被压到 0 高，滚动条出现在面板内部而不是图上。
- **用户感知**：先点任务再点消息（很自然的操作顺序，两者都在图上），图突然消失，只剩两块文字；用户不知道图去哪了，也不知道怎么回去。
- **改法**：改为**单一底部抽屉**：高度 `min(320px, 42%)`，内部两个 tab「任务 / 消息」（tab 高 28px，active 下划线 2px brand）；点消息时若任务面板开着 → 切 tab 而不是叠面板（选择状态仍可保留，符合现有独立选择的数据模型）。抽屉头固定 32px，正文滚动。

### P0-06 全图数据文本 11px + tertiary 3.71:1，低于 AA

- **证据**：11px 用于轴刻度（`styles.ts:250-257`）、泳道计数行（`styles.ts:191-202`）、活动词（`styles.ts:602-610`）、任务标题（`styles.ts:370-377`）、图例（`styles.ts:1188`）、菜单（`styles.ts:570`）、详情键名/值（`styles.ts:1150-1152`）、notice（`styles.ts:1171-1173`）；tertiary 实测亮 `3.71:1`、暗 `7.36:1`。字号 token 本身是 `11px/14px`（宿主主题包定义），即**最小可用字号被用作正文**。
- **用户感知**：亮色皮肤下，泳道计数、刻度、图例、详情键名全是"灰得发虚的 11px"，在 1x 屏上（侧边栏宽度不受缩放限制时）可读性明显下降；长会话里读数很累。
- **改法**：数据文本统一升到 `--dsw-font-xxs-12`（12px/18）并改用 `label-secondary`（亮 5.80:1 / 暗 10.42:1）；11px 仅保留给 build 行与装饰性辅助（时间轴刻度可保留 11px，但颜色改 secondary）。同步收紧 lane 高度预算：72px 内 3 行 12px/18 → 18+2+18+2+（活动词 18）= 58，仍 < 66 内高，可行。

## 2. P1 — 层级与视觉噪声

### P1-01 消息方向只剩"镜像箭头"一种编码；`solid/hollow` 已死，但样式注释仍在描述它

- **证据**：`shape: 'solid' | 'hollow'` 只写进 `data-msg-shape`（`GanttChart.tsx:1777,1867`），SVG 两侧都是 `fill="none" stroke=2`（`GanttChart.tsx:2389-2396,2457`），接收方向是 `scale(1,-1)`（`GanttChart.tsx:2499`，"deliberately still NO filled parameter" `2496-2499`）；而 `styles.ts:865-867` 仍写着"it is filled when this lane SENT … outlined when it received"。图例也用同一 SVG（`GanttChart.tsx:951-962`）。
- **用户感知**：11px 的两个镜像斜箭头，方向区别只剩"头在右上还是右下"，在深色底 + 彩色 ink 下极易看反；"这条是本泳道发出还是收到"是这张图最常被读的信息之一。
- **改法**：在**不违反 R12（无外框、同粗细）** 的前提下恢复第二编码：①发出箭头在头部加 1.5px 实心三角（fill=ink，仍是同一 path，可行）；②或让发出箭头 `stroke-width:2.2 / 圆帽`、收到 `dasharray:2 1`（虚线不算外框）；③或在标记下方 1px 处画 3px 宽的方向条。图例必须与实现同步（现在 CSS 注释已经和实现不一致，必须在改版时二选一）。

### P1-02 状态字形没有任何图例，且 idle 把整行降透明

- **证据**：状态字形映射 `running ▶ / idle ⏸ / provisioning … / failed ✕ / pending ○ / in_progress ▶ / completed ✓ / deleted ⌫`（`status.ts:33-42`），图区渲染 `STATUS_GLYPH[status] ?? '·'`（`GanttChart.tsx:1138-1144`）；图例只解释了 turn/step/任务卡/发出/收到/等待/迁移事件，**没有一条解释这些状态字形**（`GanttChart.tsx:918-1003`）；字形实现为 11px（`styles.ts:229`），idle 行 `opacity:.72`（`styles.ts:136`）。
- **用户感知**：`⏸`/`…`/`○` 三个符号在 11px 下几乎无法区分，且"某泳道到底是空闲还是在启动"没有文字兜底（红线 R2 已删状态词）。
- **改法**（不违反 R2）：①字形升级到 12px 且统一为几何符号（用 8px 圆点/环/脉冲环，不用字体字符，避免字体差异）；②图例新增"状态"段：`● 运行中 / ○ 空闲 / ◌ 启动中 / ✕ 失败`（文字在图例里，不在泳道行里，因此不构成"重复显示"）；③idle 的 `opacity` 改为只作用于 pill 之外的装饰，或 0.85。

### P1-03 图例一条栏承担三件事：缩放控件 + 图例 + 诊断信息

- **证据**：`.dtg-legend` 是唯一底部容器（`styles.ts:1188`），内部依次是 3 个缩放按钮（`GanttChart.tsx:919-927`）、读数（`928-932`）、spacer、5 项图形图例（`934-968`）、抽稀诊断（`969-976`）、迁移事件图例（`984-992`）、结束态（`993-997`）、未绘制任务诊断（`998-1002`）。11px + gap 6 → 常见状态单行需要 ≈620px、出现等待+抽稀时 ≈850px（估算：CJK≈11px/字、拉丁≈6px/字）；面板满宽 480px，扣 padding 后可用 ≈468px，因此必然折成 2–3 行（`.dtg-legend` 在 `.dtg-chart` 内，是全宽而非时间区宽度）。
- **用户感知**：底部出现 3 行小字，其中一半是"5 秒/像素""7/12 条消息已绘制"这类诊断；真正的图例被挤到第二、三行，且和缩放按钮混在一行，像工具栏。
- **改法**：拆成两段，各 24px 高：**左段**缩放（− ⤢ + 读数，`gap 2`，读数右对齐 48px）；**右段**图例（默认只显示 4 项：turn / step / 任务卡 / 等待；其余收进「?」按钮，点开为浮层，浮层里放全部符号 + 颜色规则）；诊断类（抽稀比例、未绘制任务、build）移入「?」浮层或工具栏 overflow 菜单。总高固定 24px（原最多 48px）。

### P1-04 左列角标写「活动」，但它下面第一行是消息轨；三条轨没有任何行名

- **证据**：角标文案取 `activityLabel`（`GanttChart.tsx:731-733`），而轨顺序是 message → activity → task（`timeline-layout.ts:243-256,81-84`），消息轨在最上（红线 R9）。
- **用户感知**：用户会把最上面一行（箭头/气泡）当成"活动"，把中间那条 turn/step 当成别的东西；三条轨的纵向语义全靠猜。
- **改法**：角标区 28px 内改三行 9px 小字：`消息`(y 0-9) / `活动`(10-19) / `任务`(20-28)，与三条轨的 y 对齐（3/17/30 取整到网格）；或角标保留「teammate」并在右侧 8px 处加三条 2px 引导线。若 28px 放不下三行，可将轴高从 28 增到 32（`DEFAULT_HEADER_HEIGHT`）。

### P1-05 冻结态与 live 态看起来一样

- **证据**：轴右端药丸在冻结时改用类 `dtg-now-head-ended`（`GanttChart.tsx:1287`），但 `styles.ts` **没有这个类**（只有 `.dtg-now-ended` 用于竖线，`styles.ts:1120-1124`），所以冻结时仍是 brand 实底药丸；文字变「结束 HH:mm」（`GanttChart.tsx:1295-1298`）；工具栏冻结 chip 是长文本（`BoardView.tsx:537-540`）。
- **用户感知**：团队停了以后，图看起来还在"直播"，只有读字才知道停了；而工具栏又突然变成长时间段文本，信息密度跳变。
- **改法**：①补 `.dtg-now-head-ended`：`background: bg-layer-3; color: label-secondary; border-left/right 1px dashed label-dimmed`；②冻结 chip 改两段式「已结束 · 14:24」，完整区间进 tooltip；③冻结时轴右缘画 4px 斜线端帽（表示"到此为止"），live 时圆点脉冲。

### P1-06 悬停浮窗声明可滚动，但 `pointer-events:none` 让它不可能被滚动或复制

- **证据**：`.dtg-popover { pointer-events:none; overflow:auto }`（`styles.ts:394-412`），`.dtg-popover-body { max-height:160px; overflow:auto }`（`styles.ts:441-448`）；注释还写着"the body still scrolls when the viewport genuinely cannot hold it"（`styles.ts:410-412`）。
- **用户感知**：提问浮窗 4 个问题需要 400–550px（`GanttChart.tsx:2466-2468` 注释），一旦超过视口可用高度就只能看到被截断的内容，且无法滚动、无法选中复制正文 —— 用户会认为"内容显示不全"（这正是 `CHANGELOG.md:72-96` 报过的问题）。
- **改法**：浮窗改为 `pointer-events:auto`（用 120ms 关闭延迟 + 鼠标进入浮窗时保持打开），或对"内容超过 X 高度"的情况直接提供「展开」入口 → 打开底部详情抽屉（P0-05 的同一套抽屉，复用）。必须同时给浮窗 `aria-describedby` 关联（见 A-3）。

### P1-07 关键解释只存在于 `title` 里：颜色语义、抽稀规则、等待纹理

- **证据**：颜色规则"标记颜色=对端泳道色"只在 `title={messageLegendHint}`（`GanttChart.tsx:951,957`）；抽稀规则只在 `title`（`969-970`）；等待纹理只在 `title`（`964`）；图例项是 `<span>`（不可聚焦，`styles.ts:1189`）；最小字号 11px。
- **用户感知**：不悬停就永远学不到这套编码；触摸设备上完全不可达；新用户第一眼看到的是一排彩色箭头和灰带，没有任何解释。
- **改法**：把三条规则做成**常显的一次性提示**：图例「?」浮层（见 P1-03）里用 3 行 12px 文字 + 示例图形；首次打开面板时在图区底部显示一条可关闭的提示条（24px 高，`bg-layer-2`，右端 ✕），关闭状态存 localStorage。

### P1-08 时段筛选只在「跟随」开启时才锚定左边界，关掉跟随后旧内容仍每个 tick 被推走

- **证据**：`anchorStart` 的 effect 里 `if (!followActive || span === null) { setAnchorStart(null); ... }`（`GanttChart.tsx:427-433`），注释也承认"`null` 意味着 … follow is off — both keep the previous behaviour exactly"（`GanttChart.tsx:336-352`）。而用户当初的抱怨正是"旧内容不要动"（`GanttChart.tsx:317-330`）。
- **用户感知**：手动关掉跟随后选「最近 5 分钟」，图每 5 秒把已画好的任务往左推一次，正在读的内容被推走 —— 这是用户已经明确抱怨过一次的同一现象，只是换了个开关状态。
- **改法**：锚定与 follow 解耦：只要 `windowSpanMs != null` 就锚定 `anchorStart`（follow 只决定右缘是否推进）；follow OFF 时右缘固定在锚定时刻，等价于"冻结的时间窗"，视觉上必须给出明确态（P1-05 的冻结样式复用）。

### P1-09 详情面板把原始 `laneId` / `sessionId` 当用户文案

- **证据**：任务详情「泳道」值 = `task.laneId`（`BoardView.tsx:831-833`）；消息详情「所在泳道」值 = `laneId`（`BoardView.tsx:750-753`）；历史列表每行拼 `${event.sessionId}`（`BoardView.tsx:884-886`）。
- **用户感知**：出现 `session-01H…` 这种机器 id，既不可读也不可对照（泳道上明明写的是 `host-data`）。用户无法确认"这条任务属于谁"。
- **改法**：显示泳道显示名（`selectedMessage.laneName`、或由 `laneId → lane.name` 建 map，`GanttChart.tsx:495-499` 已有同类 map），session id 折叠为末 6 位 monospace + 全量 tooltip。

### P1-10 消息标记间距 9px < 标记宽度 11px，相邻标记必然重叠；`+N` 徽标还会压住下一个

- **证据**：`MESSAGE_MARKER_MIN_GAP_PX = 9`（`timeline-layout.ts:472`）与 `MESSAGE_MARKER_WIDTH = 11`（`474`）——文件自己注释承认重叠是已知未修项（`466-471`）；标记盒再左移 9.3px 让尖端落在时间点（`GanttChart.tsx:2536,1794`）；`+N` 徽标从 `left:12px` 开始（`styles.ts:1086-1094`），而相邻标记中心只隔 9px。
- **用户感知**：消息密集的泳道（真实日志里单泳道 50+ 条）箭头会连成一片，`+N` 数字叠在下一个箭头上，变成噪点；判断不出"这里是一条还是三条消息"。
- **改法**：`gap` 提到 13px（≥ 标记宽 + 2），`MESSAGE_MARKER_MAX` 从 40 降到 24；`+N` 徽标移到标记**上方** -9px（消息轨 y=3 → 徽标 y=-7 需把 message track 下移 2px 或把徽标放在泳道底部空白区 10px 内）；或把 `+N` 合并成一个"簇标记"（一个小方块 + 数字），只在簇位置画一次。

### P1-11 `deleted` 状态被显示成「已完成」

- **证据**：`TASK_STATUS_TEXT.deleted = () => t('statusCompleted')`（`status.ts:16`）。
- **用户感知**：被删除的任务在详情里显示"已完成"，用户以为是做完了；这是状态事实错误，不只是文案问题。
- **改法**：在 `labels.ts`（ui 自己的词典，`labels.ts:21-168`）补 `statusDeleted: '已删除'`，`status.ts` 改为查该键（不改 shell 的 `i18n.ts`，避免跨 owner 写文件）。

### P1-12 单位与本地化混用：`1h 2m 3s`、`5m/15m/1h`、`秒/像素` 三种语汇

- **证据**：`formatDuration` 输出 `9s` / `2m 3s` / `1h 2m 3s`（`timeline-layout.ts:1413-1422`）；范围预设写死 `5m/15m/30m/1h/3h`（`BoardView.tsx:49-55`）；缩放读数却是中文 `5 秒/像素`（`labels.ts:144`）；任务详情用中文全角括号 `（时长）`（`labels.ts:121`）。
- **用户感知**：同一块界面里三套单位写法，且 `1h 2m 3s` 混排在中文句子中显得是半成品。
- **改法**：统一为中文单位：`9 秒` / `2 分 03 秒` / `1 小时 02 分`；预设改「5 分钟 / 15 分钟 / 30 分钟 / 1 小时 / 3 小时」（select 宽度从 72 → 96px）；读数固定 1 位小数。
