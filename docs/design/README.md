## 3. 走查结论（24 条，详见 02 页）

P0（6）：
1. 工具栏固定宽约 500px > 480px，右侧「9 任务 / 刷新」被裁，`scrollbar-width:none` 还隐藏了可滚动提示。
2. `BoardView.tsx:499` 的 `return null` 早于加载/错误分支 → **首屏空白、失败无重试**（加载/错误态是死代码）。
3. 正文级文字 11px 起，深色 tertiary 实测 3.71:1，窄任务条只能显示「…」。
4. 任务卡下另画 ＋/▶/✓ 三类事件字形，需要图例才能解释。
5. 任务详情 45% + 消息详情 60% 可同时打开，图区可被压到 0。
6. 底部 11 项图例 + 构建号占约 15% 高度，图比图例更难读。

P1 / P2 见 02 页与 `UX-AUDIT.md`。一句话结论：**不是「样式不好看」，而是信息层级、编码通道与控件可达性同时失守**。

### 4.1 「任务什么时候被认领」怎么表达（05 页）

任务条本身只回答两件事：左端 = 创建，右端 = 完成（或 NOW）。认领是条内的一个**时刻**，而 22px 高的条里文字占 5—17px，任何竖线都会压字，所以把表达放在**条下 2.5px 处的一条双段轨**上：

- 灰段（`label-tertiary` 30%）：创建 → 认领，即「排队等待」；
- 蓝段（`business` 55%）：认领 → 结束，即「执行中」；
- 交界处 2×7px 的强调色刻线：**认领 / 开始执行的那一刻**；
- 未认领的任务：整段灰、无刻线、右端开口；
- 无历史任务：仍是 9px 实时标记，不编造区间；
- 悬停 / 打开详情时，刻线读作时间（如「认领 16:02:10」），任务详情里同时给出三点时间线。

规则（实现时按数据来，不按比例硬编码）：取 `history` 中最后一次 `created` / `reopened` 之后的第一条 `claimed`；没有 `claimed` 就是未认领；多条 `claimed` 只标第一条，其余在详情的「状态迁移」里列。

## 5. 点开之后看到什么（05 页）

- **任务详情（点任务条）**：标题 + 状态 chip + 三点时间线（创建 / 认领 / 完成）+ 负责 / 依赖 / 泳道 / 写入范围 / 版本 / 时长 + 描述 + 状态迁移列表；底部抽屉覆盖图，不压缩图区，Esc / ✕ / 点空白关闭。
- **消息详情（点 ↗ / ↙ 箭头）**：方向 chip + 路由（如 `host-data → ui`）+ 时间 + 类型 + 正文全文；发出与收到共用一套抽屉。
- **问题详情（点红色 ?）**：标题行用「圆点 + 词」表达状态（等待回复 / 已回答 / 提问失败），不用描边 chip；每题 = header + 完整问题 + 答案（已选 label 前打 ✓），不列未选选项与选项说明；多选多行、自由输入单独一行；空结果写「结果中未记录选项选择」；失败只给错误码与原因。
- **一次 `ask_user_question` 可带 1—4 个问题**（实测 63 次调用：1/2/3/4 个分别是 35/15/10/3 次）：抽屉里逐题渲染「header（有则显示）+ 完整问题 + 答案」，答案只打印已被选中的 label（可多个）与自由输入，**不列未选选项和选项说明**；等待中只有问题；失败只给错误码与原因；结果不可解析时显示原文而不是假装有答案。
- 三个抽屉互斥，同一时刻只有一个；打开时图中对应标记加 1.5px focus 环。
- **方向纠正**：接收箭头 = 发出箭头的**垂直镜像**（↘），不是 180° 旋转（↙）。源码里是 `RECEIVED_ARROW_TRANSFORM = 'scale(1,-1)'`（`GanttChart.tsx:2499`），主界面、浮层、图例与设计规范页已全部按 ↘ 重画。
